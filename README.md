# BEINI

Сайт ресторана BEINI в Назрани: меню, корзина, доставка и самовывоз через
Go API и iikoCloud/iikoFront. Бронирование формируется как сообщение в WhatsApp.
Frontend: HTML, CSS и Vanilla JavaScript; backend: Go 1.24.

В локальной ветке исправления меню от 2 ноября каталог расширен до 275 позиций:
251 для текущей витрины и 24 скрытые `NEW` до запуска нового меню.
Исправлены привязки прежних 35 карточек, добавлена проверка имени источника.
По решению владельца все фото блюд заменены нейтральными заглушками,
шесть обычных позиций с неподдержанным форматом исключены из ассортимента.
Изменения ещё не опубликованы. [Результаты и ограничения](docs/tasks/menu-completeness-2026-11-02.md).

Основной сценарий заказа реализован. Готовность публичного запуска требует
отдельной приёмки: статусы заказа, повторные попытки, уведомления смене и окружение
имеют открытые задачи. См. [roadmap](docs/roadmap.md).
Отправка заказа в iiko сама по себе не доказывает оплату или фискализацию.

Интеграционная версия подключает файловый журнал заказов, GET статуса,
синхронизацию меню и стоп-листа, динамическую витрину, поиск, подтверждение
изменившихся цен и восстановление ожидания после refresh/рестарта.
2 ноября меню переведено на API v3; реальный самовывоз через UI получил
`confirmed/Success` и подтверждён скриншотами iikoFront как заказ №12540.
Отмена теста и оставшаяся приёмка фиксируются отдельно.
Уведомления Telegram подключены с сохраняемыми ack/retry
и проверены через mock transport; нужны реквизиты и внешняя приёмка. Публичное
размещение и кассовая приёмка остаются следующими этапами. См. [результат интеграции](docs/tasks/integration-2026-11-01.md).

## Быстрый старт

Нужны Go 1.24, Python 3.10+ и Node.js 22+ для проверок.
Docker с Compose необязателен. npm-зависимостей и frontend-сборки нет.

```sh
git clone https://github.com/XDobriev/beini.git
cd beini
python scripts/check.py
```

Автопроверки не используют ключи ресторана и не отправляют заказы в iiko.
Go-тесты используют loopback mock-серверы.

Для offline-проверки интерфейса без конфигурации: `python scripts/mock-ui.py`,
затем http://127.0.0.1:8765. Этот стенд не связывается с iiko.

Для запуска приложения на localhost:8080:

1. Скопируйте iiko_config.example.json в iiko_config.json.
2. Задайте `externalMenuId` (либо `IIKO_EXTERNAL_MENU_ID`) существующего внешнего
   меню, доступного API-ключу. Сервер использует `/api/menu/v3/by_id`;
   старый `/api/1/nomenclature` не используется runtime-синхронизацией.
   Примерные значения позволяют смотреть статическую витрину; оформление
   остаётся заблокированным до получения свежего серверного меню. Боевые значения берите из локальной конфигурации.
3. Создайте отдельный постоянный каталог **вне checkout и STATIC_DIR**, задайте
   его абсолютный путь в `BEINI_STATE_DIR` и ограничьте доступ учётной записью сервиса.
   В нём будут `orders.jsonl` (включая состав/контакты), `menu-cache.json`
   и при включении уведомлений `notifications.jsonl`.
4. Запустите:
   ```sh
   go run ./cmd/server
   ```
5. Откройте http://localhost:8080. Не отправляйте checkout с боевыми ключами
   без согласованного живого теста.

Сервер читает JSON и переменные окружения; .env автоматически не загружается.
Точный порядок настройки описан в [operations](docs/operations.md).
Шаблоны systemd/Nginx, упаковка Linux-релиза, HTTPS и откат описаны в
[инструкции развёртывания](docs/deployment.md); фактический статус публикации —
в [задаче](docs/tasks/public-deployment-2026-11-02.md).
Секреты не добавляются в Git. Для Telegram задайте только на сервере
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`; без них события накапливаются без отправки.
[Создание закрытой группы и бота](docs/telegram-notifications.md).

## Структура

- cmd/server/ — HTTP entry point, маршрутизация и раздача статики.
- internal/ — домен заказа, каталог цен, iiko, конфигурация и middleware.
- index.html, css/, js/, assets/ — гостевой интерфейс.
- data/menu_catalog.json — локальный каталог меню.
- tools/export_menu.py — согласованный offline-экспорт JS и Go fallback из JSON;
  `--check` проверяет их без записи.
- tools/ — Python-утилиты; scripts/ — общие проверки.
- docs/ — документация, спецификации, планы и контекст задач.
