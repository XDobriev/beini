## Неверные привязки: проверить до публичного checkout

Существование UUID не подтверждает соответствие его названию на сайте.
Сравнение названий всех 35 карточек с именами товаров по их текущим UUID:

| Карточка сайта | Товар iiko по текущему UUID | Цена сайта → iiko, ₽ |
|---|---|---:|
| Стейк «Рибай» | Творожные шарики | 1250 → 100 |
| Ковурма лагман | Лед | 480 → 5 |
| Ч1апильг с творогом | КОНТЕЙНЕР | 200 → 40 |
| Фирменный салат «Бейни» | Спец заказ, открытая цена | 690 → 1000 |
| Торт блинный | Стейк "Рибай" | 350 → 1250 |

В runtime локальные названия/фото сохраняются, цена берётся у товара по UUID.
`domain.Order.ResolveAndVerifyPrices` подставляет этот UUID; `IikoOrderItem`
отправляет `productId`, цену и количество без витринного названия. Следовательно,
код допускает отправку другого товара под видом выбранной карточки.
Это подтверждено данными и трассировкой кода; новый живой заказ для проверки
не создавался. Прежний успешный тест люля-кебаба проверял одну из пяти
совпадающих привязок и не доказывает корректность остальных.

Совпадают по смыслу: люля-кебаб, Байский плов, Казан кебаб, айс кофе с урбечом,
манго-маракуйя лимонад графин. Для люля-кебаба и лимонада различается оформление
названия, но видимого противоречия товара нет; это не новая кассовая приёмка.

Два текущих ID отсутствуют. По названию найдены кандидаты, замены НЕ применялись:

| Карточка | Текущий отсутствующий UUID | Кандидат UUID | Наблюдение |
|---|---|---|---|
| Фирменный ролл «Бейни» | f587b728-f064-4071-9568-ece89e63e369 | ee5ebcff-de8e-4c31-a9de-0bb5d40a8b8f | Фирменный ролл Бейни, 695 ₽, стоп 0 |
| Пицца Цезарь | dcf89927-b754-4e81-b11e-4b951a8dc1d4 | c529dce2-4c75-469e-b5f7-d4b9ea4fcdd1 | Пицца Цезарь, 550 ₽, нет в стопе |

Полная сверка: [current-bindings.csv](menu-completeness-2026-11-02/current-bindings.csv).
У 26 карточек статическая цена отличается от цены, которую текущий runtime

нельзя трактовать эти различия как обычное изменение цен блюд.

## Технические фильтры и стоп-лист

Все 313 продуктов представлены ровно одной позицией в группах. Повторяющихся
productId, сирот словаря и compound-позиций без productId в этом снимке нет.
Все имеют `orderItemType=Product`; необязательное `type` отсутствует у всех.
Скрытых групп/позиций/цен и group schedule в ответе не обнаружено.
Они не объясняют текущий массовый пропуск, хотя адаптер их блокирует.

У каждой позиции ровно одна положительная цена, `sizeName` пустой, `sizeId`
отсутствует. `menuItemSizeId` — идентификатор записи внешнего меню; он сам по
себе не означает выбираемый размер заказа. Размерных вариантов, явной весовой
продажи, маркировки и splittable в полученных полях нет. Разные объёмы лимонадов
заданы отдельными продуктами; нельзя объединять их ID как дубликаты.
`measureUnit` пустой у всех 313; `weight` из записи меню не доказывает массу
готовой порции или единицу продажи. Автоматически переносить вес/делить цену
по нему нельзя. Отсутствующие необязательные флаги трактуются текущим адаптером
как false; для расширения allowlist нужно подтверждение продаваемой позиции.

Шесть позиций с `canSetOpenPrice=true`:

- Чечевичный суп, 5 ₽;
- NEW Тыквенный крем суп, 5 ₽;
- Грибной крем суп, 5 ₽;
- NEW Цветные фрикадельки с лапшой, 5 ₽;
- Бой посуды, 50 ₽;
- Спец заказ, 1000 ₽.

Их блокирует формат открытой цены. Цены 5 ₽ не следует публиковать как цену
порции. «Спец заказ» уже ошибочно привязан к салату в существующем seed.

Четыре позиции с modifierGroups:

- Фергана в сливочном или кисло-сладком соусе;
- Чаи обычные;
- Сок в ассортименте стакан;
- Сок в ассортименте графин.

У соков явно обязательный выбор: minQuantity=1, maxQuantity=1. Для ферганы
и чая минимум явно не задан, но текущий checkout не поддерживает никакие
модификаторы. Нельзя молча выбрать первый или отбросить группу. 19 записей
словаря модификаторов не входят в 313 продуктов и не считаются отдельными блюдами.

Стоп-лист выбранной организации/терминала содержит 10 продуктов с balance<=0:
Шашлык Наполеон, Лагман, Пхукет, Падтай, Фирменный ролл Бейни, Говяжье ребро,
Дулх хьалтам с курицей, Манты узбекские, Говяжья голень, Салат "Ташкент".
У дулх хьалтам с курицей balance=-12, у остальных 0. Все десять UUID вне
текущего seed. Поэтому среди нынешних 35 runtime даёт 32 доступных и 3
`not_sellable`, а не три остановленных блюда. Эти три: два отсутствующих ID
и салат, ошибочно привязанный к открытому «Спец заказу».

Стоп не удаляет карточку из серверного снимка. После редакционного добавления
карточка должна отображаться недоступной, а выход из стопа менять только наличие.
Снятие стопа само по себе не добавит UUID в allowlist.

## Что фактически отдаёт публичная витрина

Read-only HTTP-проверка [GitHub Pages](https://xdobriev.github.io/beini/):
главная и JavaScript возвращают 200, `/api/menu` и `/beini/api/menu` — 404.
Frontend вызывает именно абсолютный `/api/menu`. Публичный `menu-data.js`
побайтно совпал с локальным (SHA-256
`ee628659a5f9f692fc16b36cc1a0a1921d0b6939e9108323863c5dabc81318ee`).
Публичный `app.js` совпадает с локальным после нормализации CRLF/LF.
Выполнение публичного MENU_DATA через Node VM дало 8 разделов и 35 позиций;
все 35 проходят текущие фильтры UUID/цены/категории/пути изображения.
Дополнительных пропусков из этих 35 фильтр frontend не обнаружил.

Pages показывает статический список и его цены. Актуальные цены/стопы iiko
до него не доходят, оформление блокируется. Подключение Go API исправит
обновление существующего allowlist, но само по себе не расширит меню и не
исправит неверные UUID. VPS/DNS/HTTPS в этой задаче не проверялись и не менялись.
