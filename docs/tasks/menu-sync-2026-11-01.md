   получить в этой среде. Форматы fixtures основаны на существующем nomenclature
   источнике проекта; не считать совместимость с рестораном подтверждённой.
2. Проверить token provider и выбор organization/terminal в среде интеграции.
3. По инструкции подключить worker, постоянный кэш вне web-root, `/api/menu`,
   request-scoped Pin и общий idempotency store в main.
4. Подключить frontend к endpoint; реализовать подтверждение изменившихся цен
   перед checkout отдельной задачей (текущий order API цену гостя перезаписывает).
5. После проверки diff создать commit по отдельному поручению, интегрировать
   выбранным владельцем способом. Другие ветки не объединялись.

- `python scripts/check.py`: успешно, все шаги. Go tests/vet, сборка сервера,
  синтаксис JS, 35 позиций JSON/JS/Go, 13 Python-тестов и локальный аудит 35/35.

- `go test -race -timeout 60s ./internal/catalog ./internal/menusync`: не выполнен
  до запуска тестов: gcc/MinGW не находит `crt2.o`/`crtbegin.o` по пути с кириллицей.
  Повтор с коротким Windows-путём к gcc дал ту же ошибку. Нужен рабочий C toolchain
  либо запуск `-race` на Linux; обычные concurrent-reader тесты прошли.
- Браузерная UI-приёмка не проводилась: UI не менялся.
- Live API, реальные заказы, развёртывание и отправка сообщений не проводились.

## Блокеры и вопросы

Схема актуальной версии iiko не подтверждена; прямая загрузка официальной
документации завершилась timeout, web-reader видит только оболочку справочника.
Нет блокера для сохранения кода/fixtures и offline-проверок. Подключение runtime
отдельно поручено интегратору. Race-проверка ограничена локальным MinGW.
