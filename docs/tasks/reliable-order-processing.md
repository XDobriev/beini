# Надёжная обработка заказа: передача интегратору

Статус: серверная часть завершена; подключение в main и frontend вне этой задачи.
Обновлено: 1 ноября 2026.
Ветка: main. Исходный commit: `2f992f1cec703e281f9ad436ead579c8cfe1876a`.

## Цель и критерии приёмки

Различать подтверждение/ожидание/отказ, доводить pending до итога опросом,
сохранять одну попытку на ключ, восстанавливать состояние после остановки.
При неопределённом ответе не повторять create и не обещать exactly-once iiko.
Не изменять frontend, меню, импортёр и cmd/server/main.go; Telegram не подключать.

## Контекст и решения

Контракт, ограничения и готовый фрагмент подключения:

Архитектурный выбор: [ADR 0002](../decisions/0002-durable-order-attempts.md).

## Сделано

- internal/orderstate: журнал с Sync/checksum/OS lock, восстановление неполного
  хвоста, блокировка при ошибках записи, без TTL и автоматической очистки.
- internal/handler: одна попытка create, независимость от disconnect клиента,
  worker, GET статуса по ключу, актуальный результат повтора и безопасные ошибки.
- internal/iiko: передача сохранённого ID, раздельный submit/by_id, проверка
  совпадения ID, запрет HTTP redirects. Старый синхронный API утилит сохранён.
- internal/idempotency: совместимость конструктора и отсутствие истечения
  активного legacy lock; записи заказов хранятся отдельно от TTL кэша ответов.
- Mock-тесты потери ответов iiko/HTTP, ожидания/отказа, повторов, восстановления,
  сбоя сохранения, одновременного запроса, неизвестного статуса и журналирования.
- Обновлены README, product, architecture, roadmap, operations и testing.

Изменения не закоммичены. В начале задачи уже был изменён
docs/superpowers/plans/2026-10-30-telegram-order-notifications.md; его изменение
не относится к этой работе и сохранено.

## Проверки

1 ноября 2026: `python scripts/check.py` прошла полностью с доступом к loopback:
Go tests/vet, сборка сервера, синтаксис JS, согласованность меню, 8 Python-тестов,
аудит 35 позиций. С боевой конфигурацией сервер не запускался, заказы не отправлялись.

`go test -race ./internal/handler ./internal/idempotency ./internal/iiko ./internal/orderstate`
не собрал тесты: GCC/ld не находит crt2.o/crtbegin.o через кириллический путь.
Повтор с коротким путём к GCC дал тот же результат; отсутствие гонок detector не подтвердил.
`git diff --check` для файлов задачи прошёл; общий diff отдельно показывает
уже существующую пустую строку в конце чужого Telegram-плана.
UI/боевой iiko, отключение питания и несколько реплик не испытывались.
Кросс-компиляция тестовых бинарников handler/orderstate для Linux/amd64 с
CGO_ENABLED=0 прошла вне sandbox; выполнение под Linux не проверено.

## Блокеры и вопросы

В границах серверных пакетов блокеров нет. Текущий main использует память и не
регистрирует GET статуса. После неопределённого create и остановки до отправки
возможен бессрочный pending, требующий ручной сверки; новый ключ может дать дубль.
