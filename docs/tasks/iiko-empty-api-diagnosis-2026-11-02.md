## Подтверждено прямыми запросами

Запросы выполнены отдельно от Go-сервера и frontend с локальной конфигурацией.
ENV-переопределений параметров iiko в процессе проверки нет.

- Авторизация `/api/v2/access_token` успешна. Проверены варианты `apiLogin`
  и `apiKey`; отсутствие данных воспроизводится с обоими.
- `/api/1/organizations` возвращает одну организацию, совпадающую с конфигурацией.
- `/api/1/terminal_groups` с `includeDisabled: false` возвращает
  `terminalGroups: []` и `terminalGroupsInSleep: []`.
- Тот же запрос с `includeDisabled: true` возвращает одну группу
  «Основная группа», версия POS `9.4.9102.0`. ID группы совпадает с
  `terminalGroupId` конфигурации. Следовательно, группа зарегистрирована,
  но исключается API как отключённая; это не отсутствие кассы в справочнике
  и не опечатка ID в настройках сайта.
- `/api/1/terminal_groups/is_alive` для настроенных организации и группы
  возвращает `isAliveStatus: []`. Это отсутствие статуса, а не явный `isAlive: false`.
- `/api/1/nomenclature` с `startRevision: 0` и без него возвращает пустые
  `groups`, `productCategories`, `products`, `sizes`; revision `1740470265736`.
  Это не потеря данных при парсинге и не фильтрация блюд нашим адаптером.
- `/api/2/menu` возвращает пустые `externalMenus` и `priceCategories`.
  Доступного через этот ключ внешнего меню нет.
- `/api/1/stop_lists` без фильтра группы и с корректным `terminalGroupsIds`
  возвращает `terminalGroupStopLists: []`. Это не подтверждение, что все
  блюда доступны: отсутствуют данные организации/терминала.

## Сверка с официальной схемой

Свежий GET `https://api-ru.iiko.services/api-docs/docs` выполнен без credentials.
Описание `includeDisabled` подтверждает включение отключённых групп.
Источник `/api/1/nomenclature` — RMS Data Exchange Export menu; наличие блюд
на кассе само по себе не доказывает заполнение этой отдельной выгрузки.
Метод deprecated, рекомендуемая замена — `/api/menu/v3/by_id`, но для него
нужен `externalMenuId` из `/api/2/menu`, который сейчас пуст.
Одна замена endpoint не обеспечит меню без настройки источника.

В схеме авторизации v2 требуется поле `apiKey`; код использует `apiLogin`.
Это отдельное расхождение контракта, но причиной текущих пустых ответов
его считать нельзя: с `apiKey` результат также пуст.
Объявлять отключение legacy-метода по календарной дате без подтверждения iiko нельзя.

## Ограничения и следующий шаг

Не установлено, почему группа отключена: не проверены текущая галочка доступа
в iikoWeb и логи транспортного плагина кассы. Предыдущее наблюдение красного
статуса и последней связи 30 октября — в предыдущем отчёте, не свежая UI-проверка.
Открытый iikoOffice обнаружен, но дальнейшая навигация не выполнена:
окно свёрнуто, UI helper требует `activate_window`, которого нет в текущем
интерфейсе `cua_repl`. Настройки iikoOffice не менялись.

Следующий шаг: в iikoWeb → Настройки Cloud API → Организации → Мой ресторан
проверить доступ «Основной группы», текущее состояние обмена и транспортного
плагина; отдельно проверить состав выгрузки меню в iikoOffice и внешнее меню,
доступное ключу интеграции. После восстановления повторить read-only запросы.
Добавлять `includeDisabled: true` в рабочий сценарий как исправление нельзя:
это диагностический способ увидеть отключённую группу.
