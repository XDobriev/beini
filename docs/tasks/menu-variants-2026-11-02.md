## Цель и критерии приёмки

Одно блюдо с несколькими весами/объёмами — одна карточка. Разные вкусы остаются
отдельно. Гость видит цены вариантов, выбирает порцию и добавляет её в корзину.
Можно одновременно заказать несколько порций одного блюда. Сервер проверяет
каждый исходный товар независимо, прежние корзины и запрос заказа совместимы.

## Контекст и решения

Владелец согласовал предложенный подход в чате 2 ноября.
[Спецификация](../superpowers/specs/2026-11-02-menu-variants-design.md),
[план](../superpowers/plans/2026-11-02-menu-variants.md).

Поля `variantGroup`, `variantName`, `variantLabel`, `variantOrder` — редакционные,
не параметры кассового заказа. Нативные размеры/модификаторы iiko остаются
неподдерживаемыми. Миллилитры не выдумываются. При свежем меню недоступная порция
отключена; уже выбранная порция при стопе не подменяется соседней.
Без свежего API доступен только просмотр, включая переключение порций.
