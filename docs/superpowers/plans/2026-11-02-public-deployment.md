# План публичного развёртывания BEINI

**Цель:** один публичный HTTPS origin frontend/API и постоянное состояние после рестарта.
**Основа:** [проект и проверки](../../tasks/public-deployment-2026-11-02.md),
поручение владельца от 2 ноября 2026: существующий VPS Ubuntu 24.04, systemd,
Nginx, loopback 8080; чистый `/var/lib/beini`, старый локальный журнал не переносить.

## Ограничения

- Не менять `/var/www/avtorstudio` и его Nginx-конфиг. Не дублировать `map`.
- `nginx -t` перед каждым reload/restart Nginx. Другие сервисы не перезапускать.
- Секреты вне checkout/web root, Telegram не включать, заказы не отправлять.
- Постоянные orders/notifications не удалять и не откатывать; один writer.
- Обычный push без force. Чужой незакоммиченный документ сохранить.

## Риски, которые проверяем

- Bind не должен открывать 8080 наружу; неверный override не должен включать fallback.
- Upstream может вернуть контакты/секреты в error body или некорректном JSON:
  эти данные не попадают в ошибки, логи или HTTP-ответ гостю.
- Same-origin POST передаёт Origin: beinirest.ru явно включён в server allowlist.
- Certbot не переписывает сторонние vhost; reload не меняет защищённый конфиг.
- Чистое состояние согласовано владельцем; старый локальный журнал сохраняется.
  Для restart использовать синтетическую receipt-запись без заказа в iiko,
  либо файловую проверку плюс имеющиеся offline-тесты; ограничения явно записать.
