# Доставка уведомлений

Основание: поручение владельца и существующие NotificationQueue/notificationSource.

1. Закрепить тестами доставку pending перед конечным событием, retry после рестарта и дедупликацию ack.
2. Использовать отдельный orderstate-журнал delivery receipts: fsync/OS lock/checksum уже проверены; сбой не блокирует orders.jsonl.
3. Один worker сериализует отправки; сохраняет попытку и срок повтора до сети, ack после успеха. Один event может иметь несколько частей с отдельными ack.
4. Telegram sendMessage: server-only ENV, таймаут, plain text без разметки, ограничение длины, безопасные ошибки, Retry-After, запрет redirects.
5. Подключить lifecycle независимо от заказа; отсутствие реквизитов сохраняет backlog без фиктивного ack.
6. Проверить mock transport/HTTP, сбой журнала, порядок, рестарт; выполнить scripts/check.py, обновить эксплуатацию и передачу.

Ограничение: потеря ответа Telegram или crash между успешной отправкой и fsync ack допускает повтор той же части; exactly-once внешней доставки не обещается. Retention автоматически не вводится.
