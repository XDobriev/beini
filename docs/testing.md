```sh
python scripts/check.py
```

Работает из любого каталога; на Windows также доступен scripts/check.ps1.
Зависимости: Go 1.24, Node.js 22+, Python 3.10+; pip/npm-установка не требуется.
Команда выполняет Go-тесты, go vet, сборку сервера во временный каталог,
синтаксис JS, сравнение меню JSON/JS, Python-тесты импортёра и аудит каталога.
Любая ошибка даёт ненулевой итоговый код. Остальные шаги выполняются,
чтобы получить полный список ошибок.

CI выполняет ту же команду на Windows и Linux.
Сборка Docker и браузерная приёмка в эту команду не входят.

Windows CI также проверяет размещение каталога состояния на другом диске, чем
публичная статика. Extended Windows/UNC-пути не должны обходить запрет размещения
журнала внутри web root.

## Изоляция

Ключи и iiko_config.json для автопроверок не нужны. Сетевые Go-тесты используют
локальные httptest-серверы: это offline относительно iiko, но не запрет loopback.
Ограничения sandbox на сокеты или временные каталоги могут помешать проверкам.
Фиксируйте такие ограничения отдельно от ошибок приложения.

Запускайте только discovery для test_import_menu.py. tools/test_order.py —
живая утилита, а не unit-тест. Проверки не запускают сервер с боевой конфигурацией.

## Проверки обработки заказов

`internal/handler/order_tracking_test.go` использует mock iiko: InProgress с
последующим Success/Error/Cancelled, сбой by_id, потеря ответа create после
создания, потеря HTTP-ответа гостю, одновременный повтор и disconnect, автоматический
worker, восстановление из файла, остановка до отправки, недоступность записи
до/после create. Проверяются отсутствие второго create и актуальный итог повтора.
Тесты `internal/orderstate` проверяют эксклюзивного writer, восстановление,
конкурентную резервацию, незавершённый хвост, повреждение полной записи и
блокирование Store после ошибки записи. В iiko проверяется точное соответствие ID,
запрет HTTP redirects и некорректный ответ. Активный legacy lock не истекает по TTL.

Локальная проверка 1 ноября 2026: `python scripts/check.py` прошла с разрешённым
loopback. Обычный запуск `go test -race` и повтор с коротким путём к GCC
не собрали тесты: GCC/ld не разрешил
кириллический путь установки к crt2.o/crtbegin.o; это ограничение toolchain,
а не успешная проверка отсутствия гонок. Эти тесты не доказывают поведение
боевой кассы или диска при
отключении питания. UI не менялся и в рамках этой задачи не проверялся в браузере.
Тестовые бинарники handler/orderstate также успешно скомпилированы для Linux/amd64
с CGO_ENABLED=0; выполнение тестов под Linux здесь не проводилось.
