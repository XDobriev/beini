# Проверки

## Общая команда

```sh
python scripts/check.py
```

Работает из любого каталога; на Windows также доступен scripts/check.ps1.
Зависимости: Go 1.24, Node.js 22+, Python 3.10+; pip/npm-установка не требуется.
Команда выполняет Go-тесты, go vet, сборку сервера во временный каталог,
синтаксис JS, сравнение меню JSON/JS, Python-тесты импортёра и аудит каталога.
Любая ошибка даёт ненулевой итоговый код. Остальные шаги выполняются,
чтобы получить полный список ошибок.

CI выполняет ту же команду на Windows и Linux.
Сборка Docker и браузерная приёмка в эту команду не входят.

## Изоляция

Ключи и iiko_config.json для автопроверок не нужны. Сетевые Go-тесты используют
локальные httptest-серверы: это offline относительно iiko, но не запрет loopback.
Ограничения sandbox на сокеты или временные каталоги могут помешать проверкам.
Фиксируйте такие ограничения отдельно от ошибок приложения.

Запускайте только discovery для test_import_menu.py. tools/test_order.py —
живая утилита, а не unit-тест. Проверки не запускают сервер с боевой конфигурацией.

## Контракт меню

node scripts/check-menu.cjs сверяет ID, iiko ID, цены, категории и отсутствие
дубликатов у доступных позиций JSON и JS. Go-тест TestMenuCatalogConsistency
проверяет соответствие этих позиций серверному каталогу по обоим ID и цене.
Дополнительные серверные позиции допустимы. Локальный аудит импортёра проверяет
UUID, цены, категории и наличие фотографий.

## Ручная приёмка UI

Проверяйте мобильный и desktop viewport, а также ширины около 1024 px:
- категории, изображения, пустую корзину, добавление/удаление, суммы и восстановление;
- доставку и самовывоз, телефон и адрес, ошибки полей;
- отправку через mock API: успех, pending, отказ, timeout и повторную попытку;
- закрытие шторки, клавиатуру, фокус, прокрутку и отсутствие горизонтального overflow;
- WhatsApp-бронирование: сообщение заполняется, но без подтверждения ресторана
  не показывается как подтверждённая бронь.

Не отправляйте реальные заказы для проверки UI без согласованного живого теста.
Для повторяемой offline-проверки frontend есть `python scripts/mock-ui.py`
(loopback 8765). Переключение сценариев описано в начале скрипта; реальных ключей нет.
Это mock HTTP-контракта frontend; полный серверный сценарий проверяет Go-тест приложения.

## Как сообщать результат

Укажите команду, успешные и неуспешные шаги, ограничения среды и ручные проверки.
Не объявляйте весь набор успешным по exit code последней команды в shell.
Боевой тест и развёртывание проверяются отдельно по operations.md.

## Проверки обработки заказов

`internal/handler/order_tracking_test.go` использует mock iiko: InProgress с
последующим Success/Error/Cancelled, сбой by_id, потеря ответа create после
создания, потеря HTTP-ответа гостю, одновременный повтор и disconnect, автоматический
worker, восстановление из файла, остановка до отправки, недоступность записи
до/после create. Проверяются отсутствие второго create и актуальный итог повтора.
Тесты `internal/orderstate` проверяют эксклюзивного writer, восстановление,
конкурентную резервацию, незавершённый хвост, повреждение полной записи и
блокирование Store после ошибки записи. В iiko проверяется точное соответствие ID,
запрет HTTP redirects и некорректный ответ. Активный legacy lock не истекает по TTL.

Локальная проверка 1 ноября 2026: `python scripts/check.py` прошла с разрешённым
loopback. Обычный запуск `go test -race` и повтор с коротким путём к GCC
не собрали тесты: GCC/ld не разрешил
кириллический путь установки к crt2.o/crtbegin.o; это ограничение toolchain,
а не успешная проверка отсутствия гонок. Эти тесты не доказывают поведение
боевой кассы или диска при
отключении питания. UI не менялся и в рамках этой задачи не проверялся в браузере.
Тестовые бинарники handler/orderstate также успешно скомпилированы для Linux/amd64
с CGO_ENABLED=0; выполнение тестов под Linux здесь не проводилось.


## Интеграция 1 ноября 2026

Исторические результаты отдельных задач выше не являются результатами интеграции.
Новые сценарии: TestApplicationMenuOrderRestart — actual application assembly,
динамическое меню, конфликт цены до create, pending → confirmed/rejected, потеря
ответа, повтор и восстановление из файлов. TestDynamicOrderPinsOnceAndChecksEachPrice
фиксирует один Pin, изменение цен при одинаковой сумме и источник уведомлений.
TestNotificationSourceAndQueueSurviveRestart проверяет очередь/контакты и ID событий.
TestOfficialProductSaleContract и test_official_sale_flags закрепляют OpenAPI поля
в Go и Python. scripts/check-checkout.cjs проверяет новую корзину после terminal
attempt и блокировку редактирования при unresolved; входит в scripts/check.py.

Браузерная матрица и результаты общего запуска: [передача](tasks/integration-2026-11-01.md).
Sandbox может запрещать loopback и операции во временных каталогах. При таких
ошибках повторять offline-команду с разрешённым loopback, не менять бизнес-логику.
