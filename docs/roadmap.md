Публичная витрина находится на GitHub Pages, API запущен только локально.
Размещение на имеющемся VPS Timeweb не согласовано. Дополнительные настройки
инфраструктуры и создание реальных заказов требуют соответствующего поручения.
Условия, зона, тариф и минимальная сумма доставки требуют уточнения;
отсутствующие значения нельзя подменять бесплатной доставкой.

## Основа разработки

Серверный контракт, подключение и границы без обещания exactly-once:
[обработка заказов](order-processing.md). Main использует постоянный журнал и единый runtime Store; frontend сохраняет
ключ/тело и опрашивает результат. Telegram worker/transport подключены; без реквизитов отправка отключена. Передача и ограничения:
[интеграция](tasks/integration-2026-11-01.md).

Общие инструкции, карта документации, единая команда проверок и конфигурация CI
добавлены. Успешность CI подтверждается запуском workflow в GitHub после push;
наличие YAML само по себе не является результатом проверки.
При синхронизации нельзя трактовать сбой получения стоп-листа как пустой стоп-лист.
Этот риск исправлен: ошибка/неизвестный стоп-лист не снимают ограничения.

## Ближайшие действия после интеграции

1. Создать закрытую группу и бота по [инструкции](telegram-notifications.md),
   передать server-only реквизиты и согласовать внешнюю приёмку. Durable ack/dedupe,
   порядок pending/итога, retry и восстановление проверяются offline.
   Результат этапа: [передача уведомлений](tasks/notifications-2026-11-01.md).
2. После разрешения на read-only проверку получить меню/стопы ресторана:
   проверить доступность метода, цены, терминал, лимиты и исключённые блюда.
3. До публичной эксплуатации определить доступ и срок хранения состава/контактов,
   резервирование журнала, тариф/зону/минимальную сумму доставки.
4. Согласовать окружение показа и способ доступа к API. Изменения VPS/домена,
   публикация и затем живой тест с сотрудниками требуют отдельных поручений.

## Как поддерживать список актуальным

Roadmap — общий список приоритетов и текущих статусов. Обновлять при начале задачи,
изменении объёма/блокера и завершении; для каждой крупной задачи давать ссылку на
`docs/tasks/` с критериями, проверками и следующим шагом. Различать «проверено
локально» и «принято на кассе». После коммита фиксировать результат в документе
задачи; не дублировать подробные журналы работ в roadmap.
