# Реализованная архитектура

Срез интеграционной версии: 1 ноября 2026. Проверено локально с mock API.

| Область | Ответственность |
|---|---|
| cmd/server/application.go | Сборка зависимостей, файловые хранилища, маршруты и остановка |
| internal/catalog | Редакционный allowlist и атомарные снимки доверенных цен |
| internal/menusync | iiko номенклатура/стопы, расписание, сохранение кэша и свежесть |
| internal/handler | Валидация, подтверждение цены, идемпотентность и worker статуса |
| internal/orderstate | Append-only журнал с fsync/OS lock, источник и локальная очередь уведомлений |
| internal/domain | Телефон, адрес, ограничения состава и серверная сумма |
| internal/iiko | Токен, однократный create с ID и последующая сверка by_id |
| js/app.js | Динамическое меню, поиск, корзина, согласие с ценами и polling |

## Запуск и хранение

`BEINI_STATE_DIR` — обязательный абсолютный путь к существующему каталогу вне
публичного `STATIC_DIR`. Путь проверяется после разрешения symlink/junction.
`orders.jsonl` и `menu-cache.json` не находятся в checkout и не раздаются как статика.
Ошибка открытия журнала блокирует запуск, подмены памятью нет. OS lock обеспечивает
одного writer; меню worker стартует после получения lock. Один процесс и локальный диск.
При остановке HTTP сервер завершает запросы, worker меню отменяется и ожидается,
handler останавливает сверку/create, затем закрывается журнал.

## HTTP

| Маршрут | Назначение |
|---|---|
| GET / | Гостевой интерфейс |
| GET /api/health | Живость процесса, без гарантии связи с кассой |
| GET /api/menu | Текущий снимок и freshness, без запроса iiko на каждый GET |
| POST /api/order | Проверка цены и создание заказа с сохранённым ключом |
| GET /api/order/status | Чтение журнала по Idempotency-Key; отдельный limiter 60/мин |
| POST /api/test-order | В динамической сборке возвращает 503: фиксированный Латте не настроен |
| GET /demo | Проверка живости; кнопка фиксированного заказа отключена |

Неизвестные /api/* возвращают JSON 404. Menu/status/состояния заказа — no-store.
CORS exposes Idempotency-Key, Retry-After, X-Cache-Lookup.

## Меню и заказ

`data/menu_catalog.json` задаёт проверенные ID, фото, тексты и порядок.
`catalog.Store` получает цены и наличие из iiko; один снимок обслуживает витрину
и серверную валидацию. Меню обновляется каждые 15 минут, стопы — каждую минуту.
Свежесть: меню 2 часа, стопы 5 минут. Это локальные параметры, лимиты лицензии
ресторана ещё не проверены. Ошибка сохраняет последний снимок; просрочка запрещает
оформление. Статический MENU_DATA остаётся только fallback для просмотра.
Локальные JSON/JS/Go fallback согласуются прежними проверками; main больше не
использует статический Go-каталог для гостевых заказов.

Handler вызывает `Store.Pin()` один раз на весь новый заказ. После валидации
сверяет массив `expectedPrices` с каждой серверной строкой. 409 price_changed
содержит новые строки/сумму и не резервирует попытку. Гость подтверждает цены;
повторная отправка снова проходит проверку — согласие не фиксирует цену навсегда.

До create атомарно сохраняются UUID, хеш тела, сумма, нормализованный состав
и контакты. На один сохранённый ключ — не более одного create. Повтор с тем же
телом читает журнал ещё до меню/цены; другое тело получает 422. Worker сверяет ID
и после рестарта; отсутствие ID не разрешает новый create. Exactly-once в iiko
не обещается. Подробности: [обработка заказов](order-processing.md).

Frontend хранит ключ и неизменное тело до отправки в localStorage. Неопределённый
результат блокирует новый заказ; GET с backoff 5–60 секунд получает итог. При 404
или сбое доступен ручной повтор прежнего запроса. Confirmed очищает корзину,
rejected остаётся отдельным состоянием; новая корзина после успеха закрывает старую
terminal attempt. Персональные данные тела удаляются из browser attempt при исходе.

## Границы

[Сверка OpenAPI](iiko-schema-review-2026-11-01.md) исправила terminalGroupsIds,
строчные dish/good и useBalanceForSell. Размеры, вес, открытая цена, compound
и модификаторы запрещены. Реальный набор исключённых блюд пока неизвестен.

В журнале есть источник будущих уведомлений. `NotificationQueue()` восстанавливает
pending и конечное событие с постоянным ID. HTTP доступа к очереди нет; Telegram
transport, ack, дедупликация доставки и retention ещё не реализованы. См. ADR 0004.
Касса, оплата, фискализация, VPS, домен и публичная приёмка не проверялись.
