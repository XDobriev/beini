# Реализованная архитектура

Срез: 1 ноября 2026. Будущие изменения перечислены в roadmap.md.

## Компоненты

| Область | Ответственность |
|---|---|
| cmd/server | Конфигурация, сборка зависимостей, маршруты, статика, завершение |
| internal/handler | HTTP-контракт, размер тела, идемпотентность, ошибки |
| internal/domain | Нормализация телефона, адреса, ограничения и сумма |
| internal/catalog | Поиск доверенных названий, iiko ID и цен |
| internal/iiko | Авторизация, создание доставки, опрос результата |
| internal/idempotency | Блокировка и кэш ответа по ключу в памяти процесса |
| internal/middleware | Логи, CORS, recover, ограничение частоты |
| js/app.js | Меню, корзина, checkout и WhatsApp-бронирование |

Приложение работает одним Go-процессом. Базы данных и фонового worker нет.
Статика раздаётся этим же сервером с блокировкой служебных файлов.

## Поток заказа

1. Браузер отправляет JSON на POST /api/order с Idempotency-Key.
2. Middleware ограничивает частоту, handler проверяет Content-Type и размер тела.
3. Хранилище идемпотентности сверяет ключ с SHA-256 исходного тела запроса.
4. Domain заменяет клиентские цены/названия серверными и валидирует заказ.
5. Клиент iiko получает кэшируемый токен через /api/v2/access_token.
6. Заказ создаётся через /api/1/deliveries/create, результат запрашивается
   через /api/1/deliveries/by_id.
7. Ответ включает creationStatus, pending, orderInfo и серверную totalSum.

Кэш идемпотентности живёт 30 минут и теряется при рестарте; без ключа
обработчик не включает эту защиту. После завершения HTTP-запроса
долговременного наблюдения за pending нет. Новая попытка браузера сейчас
генерирует новый ключ. Это открытые задачи, а не гарантии надёжной доставки.

## HTTP

| Маршрут | Назначение |
|---|---|
| GET / | Гостевой интерфейс |
| GET /api/health | Живость процесса; не проверяет связь с кассой |
| POST /api/order | Создание реального заказа |
| POST /api/test-order | Реальный тестовый заказ, localhost или X-Test-Token |
| GET /demo | Диагностический интерфейс |

Точный формат и коды ошибок — internal/domain/order.go и
internal/handler/order_handler.go. Неизвестные /api/* возвращают JSON 404.

## Меню и источники данных

- data/menu_catalog.json — редактируемый локальный источник для импортёра.
- tools/import_menu.py экспортирует доступные позиции в js/menu-data.js.
- internal/catalog/catalog.go содержит отдельный список для серверной валидации.
- В серверном списке есть дополнительные latte и p1; их наличие не означает,
  что они показываются гостю.
- scripts/check-menu.cjs сверяет доступные позиции JSON с JS по ID, iiko ID и цене.
- Go-тест TestMenuCatalogConsistency сверяет эти позиции с серверным каталогом.

Единой генерации Go-каталога пока нет. Изменения меню должны обновлять все
представления; текущие проверки обнаруживают расхождение, но не исправляют его.
Стоп-лист не запрашивается в реальном времени гостевой страницей.

## Внешние границы

iikoCloud — внешний сервис с сетевыми отказами и неопределённым результатом.
JWT кэшируется в памяти. Конфигурация берётся из JSON и ENV.
Заказ не равнозначен оплате или подтверждённой фискализации.
WhatsApp открывает сообщение на стороне гостя; автоматической доставки
бронирования сервером нет. Telegram существует только в планах.

Решения и основания: decisions/README.md. Эксплуатация: operations.md.
