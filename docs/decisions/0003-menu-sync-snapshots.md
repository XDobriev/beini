# 0003: Проверенный снимок меню и стоп-листа

Дата: 1 ноября 2026.
Статус: принято для серверного компонента; runtime-подключение впереди.

## Контекст

Локальный JSON, JS и Go-каталог существуют раздельно. Нужен общий источник цены
и доступности для сервера и витрины; сбой iiko не должен снимать стопы. Заказ
пока не поддерживает размеры/модификаторы. Новинки требуют редакционного ревью.
Область задачи исключает main, frontend, handler/domain и внешние настройки.

## Решение

Добавить `catalog.Store`, общий для чтения меню и проверки заказа. Загружать
проверенный локальный allowlist, сохранять фото/тексты/порядок; обновлять цену и
доступность из номенклатуры и стоп-листа выбранной терминальной группы.
Полная версия требует успешного получения обоих источников. Отдельный более
частый polling стопов не продлевает свежесть номенклатуры. Неизвестные продукты,
размеры, весовая продажа и модификаторы автоматически не открываются.

Проверенный снимок записывать через временный файл/Sync/rename до публикации в
памяти. Восстанавливать только после проверки checksum, схемы и соответствия
организации, терминалу и allowlist. Просрочка любого источника закрывает заказ,
сохраняя данные для просмотра. В рамках одного заказа использовать `Store.Pin()`.
Вебхуки и БД не добавлять. Текущий runtime остаётся прежним до wiring интегратором.

## Альтернативы

- Live-запросы из каждого checkout: добавляют зависимость от задержек/сбоев iiko
  и не дают единой версии витрине.
- Генерация отдельных JS/Go файлов по cron: оставляет несколько источников и
  не гарантирует согласованную публикацию.
- Внешнее меню iiko: возможно отдельным Source, но актуальная схема/доступность
  не подтверждены; автоматически менять настройки/источник нельзя.
- БД и webhooks: добавляют инфраструктуру, исключены из текущей задачи.

## Последствия и ограничения

Один writer и локальный постоянный файл на организацию/терминал. После сбоя
принимается прежняя версия только до истечения её maxAge. Новое/неподдерживаемое
блюдо требует ревью; при изменении allowlist старый кэш не принимается.
История ошибок не персистится; коды и время последней попытки доступны в текущем
процессе. Контроль количества по положительным остаткам и подтверждение цены
гостем требуют отдельной интеграции заказа. Нельзя объявлять подключение готовым
по одним offline-тестам: официальную схему не удалось полностью загрузить.

Реализация: `internal/catalog/snapshot.go`, `internal/menusync`.
Контракт и проверки: [menu-sync](../menu-sync.md),
[передача](../tasks/menu-sync-2026-11-01.md).
