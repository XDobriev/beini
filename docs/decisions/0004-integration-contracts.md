# 0004: Интеграция меню, согласия с ценой и источника уведомлений

Дата: 1 ноября 2026. Статус: принято для локальной интеграционной версии.
Дополняет 0002 (журнал) и 0003 (меню); внешняя приёмка остаётся отдельным этапом.

## Контекст

Пакеты трёх задач не были подключены друг к другу. Повтор должен восстанавливать
результат независимо от текущей цены/доступности, а новый заказ — проверять
единый снимок и согласие гостя с каждой ценой. После рестарта будущему notifier
недостаточно ID/суммы: нужны контакты и проверенный состав.

## Решение

- Main требует BEINI_STATE_DIR вне web root и открывает постоянный журнал/кэш.
  Fail-open на память или статический каталог запрещён.
- Единственный catalog.Store обслуживает /api/menu и handler; Pin один раз на
  новую проверку. Повтор сохранённого key/body читается до текущего меню.
- expectedPrices сверяются по строкам до Reserve; 409 price_changed не создаёт
  заказ. Новая отправка требует явного согласия с показанными ценами, затем
  повторно проверяется сервером. Версия снимка сама по себе не подтверждает цену.
- Frontend хранит key/body до сети в localStorage, polling с backoff и безопасный
  ручной повтор; итог confirmed/rejected отличается от pending/unknown.
- Журнал расширен notificationSource: нормализованный состав и контакты
  записываются атомарно с pending до сети. NotificationQueue проецирует pending
  и конечное событие с ID orderId:status. HTTP не раскрывает эти поля.
- Telegram transport и durable ack не подключены. Очередь до ack сохраняется;
  следующим этапом нужны дедупликация, порядок, retry и retention.
- Fixed diagnostic latte отсутствует в allowlist. /api/test-order в main
  возвращает 503; /demo не предлагает отправку неподтверждённого блюда.

## Альтернативы и последствия

Отдельный файл контактов/outbox создавал бы окно между двумя записями.
Единый append-only журнал устраняет это окно, но содержит персональные данные
и растёт без очистки. Нужны ACL, защита резервных копий и решение о сроках хранения
перед публичной эксплуатацией. Исторические записи без source не дают состав.
Старое решение 0002 об отсутствии контактов сохраняется как история и дополнено
этим решением; API статуса по-прежнему их не возвращает.

Вместо автоматического выбора альтернативного test dish диагностика закрыта.
Вместо предположений по синтетическим fixtures выполнена сверка публичной OpenAPI;
deprecated nomenclature пока сохранён, миграция на menu/v3 требует отдельного решения.
