Публичное окружение, домен, HTTPS и восстановление после рестарта требуют
отдельного подтверждения. Этот документ описывает имеющиеся механизмы
и порядок проверки, а не подтверждает готовность production.

## Локальный запуск

Скопируйте iiko_config.example.json в iiko_config.json. Создайте постоянный
каталог вне checkout/STATIC_DIR, ограничьте ACL учётной записью сервиса и задайте
абсолютный путь в BEINI_STATE_DIR. Затем запустите:
```sh
go run ./cmd/server
```
Сервер читает JSON и затем переопределяет значения из ENV. Если JSON отсутствует,
нужны ENV-параметры интеграции. Примерные значения позволяют посмотреть витрину,
но не выполнять заказ. .env сервер автоматически не читает.

Параметры: BEINI_STATE_DIR, PORT, HTTP_LISTEN_ADDR, STATIC_DIR, IIKO_API_BASE_URL, IIKO_API_KEY, IIKO_APP_ID,
IIKO_CLIENT_SECRET, IIKO_ORGANIZATION_ID, IIKO_TERMINAL_GROUP_ID, DELIVERY_CITY,
TRANSPORT_TIMEOUT_SEC, TEST_ORDER_TOKEN, ALLOWED_ORIGINS, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID.
Типы заказов и оплаты задаются в JSON. Источник точной схемы:
internal/config/config.go и iiko_config.example.json.

Для меню обязательны `externalMenuId` в JSON или `IIKO_EXTERNAL_MENU_ID` в ENV.
Опциональная ценовая категория: `priceCategoryId` / `IIKO_PRICE_CATEGORY_ID`;
пустое значение использует базовый прайс внешнего меню. Меню должно быть назначено
API-ключу в iikoWeb. Отсутствие ID блокирует запуск с понятной ошибкой.
После смены ID меню или ценовой категории старый дисковый снимок не восстанавливается:
сначала требуется успешное обновление меню и стоп-листа. Журнал заказов не очищать.

Боевые секреты хранятся локально или в механизме секретов окружения.
Не помещайте их в документацию, diff, screenshot и логи проверок.

## Постоянное состояние

`cmd/server/application.go` открывает `BEINI_STATE_DIR/orders.jsonl`, восстанавливает
`menu-cache.json`, подключает worker меню и GET `/api/menu`, `/api/order/status`.
Каталог должен существовать; относительный путь или путь внутри web root (после
разрешения symlink/junction) блокирует запуск. Журнал не заменяется памятью.
В Windows права 0600 не заменяют ACL. Каталог не должен быть публичным или общим.

**Журнал теперь содержит персональные данные:** нормализованный телефон, имя,
адрес, комментарий и состав. Они нужны источнику уведомлений; при включённом
Telegram отправляются в настроенную закрытую группу, но не возвращаются GET статуса. Retention/очистка
ещё не реализованы. Перед публичной эксплуатацией согласовать доступ, срок хранения
и резервирование. Не публиковать журнал и его резервные копии, не помещать в Git.

Хранить на постоянном локальном диске; один процесс/writer. Нельзя обходить OS lock
вторым журналом для той же организации, откатывать старую копию или очищать ключи
без сверки с iiko. Журнал и кэш привязаны к конфигурации организации/терминала;
смена конфигурации требует отдельного хранилища и согласованной сверки.

Безопасный offline стенд UI: `python scripts/mock-ui.py`, порт 8765 loopback-only.
Он не читает конфигурацию iiko. `/__mock__` управляет только синтетическими данными.
Фактический restart с диском проверяется Go-тестом `TestApplicationMenuOrderRestart`.
Фиксированный `/api/test-order` в динамической сборке отвечает 503; кнопка /demo
отключена до отдельного согласования диагностического блюда и цены.

## Нативный Linux VPS

Подготовлены unit systemd, отдельный Nginx-vhost, loopback bind и изолированный
журнал. Состав релиза, HTTPS/ACME, запуск, проверки и откат:
[инструкция развёртывания](deployment.md). Результат фактической публикации
фиксируется в документе задачи; наличие шаблонов не подтверждает запуск.
HTTP_LISTEN_ADDR переопределяет адрес целиком; без него сохраняется `:<PORT>`.

## Docker

Контейнерная сборка в этой интеграции не проверялась. Старую команду запуска
Compose нельзя считать рабочей: требуется передача BEINI_STATE_DIR, persistent
volume вне web root и копирование data/menu_catalog.json в образ.

Текущий Compose монтирует iiko_config.json и задаёт PORT/TZ; остальные ключи
из .env автоматически в контейнер не передаются.
Dockerfile собирает Go-сервер и копирует статику.
Известный блокер: .dockerignore исключает *.png, включая PNG-логотипы.
До production нужно исправить состав образа и проверить страницы из контейнера.

## Проверки после развёртывания

- GET /api/health проверяет живость процесса, не кассу.
- Проверьте главную, фотографии, логотипы и корректные 404 для ассетов.
- Подтвердите HTTPS, CORS и корректное определение IP за выбранным reverse proxy.
- Проверьте restart, логи и сохранность конфигурации.
- Зафиксируйте commit/образ, время проверки и ответственного.
- Разрешение на изменение кода не означает поручение на развёртывание.

## Живой тест кассы

Только по явному поручению на живой тест с координацией персонала:
1. Подтвердите ресторан, терминал, активную смену и присутствие сотрудника.
2. Согласуйте один тестовый заказ и способ его отмены.
3. Используйте /demo, cmd/test-order или tools/test_order.py.
4. Проверьте карточку заказа, сигнал и печать, если она настроена.
5. Сотрудник отменяет тестовый заказ; зафиксируйте итог без данных гостей.

Все эти способы создают настоящий заказ. /api/test-order доступен по
X-Test-Token, если он задан, иначе — с прямого loopback без proxy-заголовков.
Обычный /api/order с боевой конфигурацией также создаёт реальный заказ.

В прежних CLAUDE.md/GEMINI.md был записан успешный живой тест 30 октября 2026
на iikoFront в ресторане BEINI. Это историческая запись, при настройке harness
он не повторялся. Подробный исторический регламент: ../TESTING_IIKO_FRIDAY.md.

## Сбой и откат

При неопределённом результате сначала сверьте заказ с кассой; повторная
отправка с новым ключом может создать дубль. Кэш идемпотентности в памяти
теряется после рестарта. Не перезапускайте процесс как способ повторить заказ.

Для отката используйте заранее сохранённый commit/образ и сохранённую
конфигурацию, затем проверьте health и статику. Конкретный механизм отката
и адреса сервера должны быть заполнены после выбора окружения.


## Уведомления Telegram

Добавлены server-only TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID (одна закрытая группа).
Без реквизитов оформление работает, события остаются в журнале. Настройка бота,
получение ID без раскрытия токена, backlog, recovery и смена группы:
[инструкция Telegram](telegram-notifications.md).
BEINI_STATE_DIR содержит также notifications.jsonl; сохраняйте его вместе с orders,
не удаляйте ради исправления ошибки отправки. Сбой этого журнала отключает только
уведомления. Перед включением проверьте накопленные события и доступ к группе.
Развёртывание и живая отправка в рамках разработки не выполнялись.
