# BEINI: инструкции для агентов

Общие правила для Codex, Gemini, Antigravity, Claude и других помощников.
Отвечайте на русском; идентификаторы и технические термины сохраняйте.
Не добавляйте атрибуцию ИИ в код, коммиты и документы.

## Начало работы и контекст

- Прочитайте этот файл, посмотрите Git status и сохраните чужие незавершённые изменения.
- Начните с README.md. Читайте подробные документы по задаче, а не весь docs/ сразу.
- Сценарии и границы продукта: docs/product.md.
- Реализованное устройство и ограничения: docs/architecture.md.
- UI: перед изменениями читайте docs/design-system.md.
- Подтверждённые вводные владельца: docs/confirmed-context-2026-11-01.md.
  Читайте перед решениями об объёме, сроках, меню и инфраструктуре; учитывайте более поздние уточнения.
- Приоритеты: docs/roadmap.md. Контекст незавершённой работы: docs/tasks/.
- Проверки: docs/testing.md. Развёртывание и живые тесты: docs/operations.md.
- Причины важных решений: docs/decisions/.
- Спецификация или план в docs/superpowers/ не означает, что функция реализована.
- Если документация расходится с кодом, проверьте поведение и обновите затронутый документ.
  Не выдавайте запланированное за готовое; сохраняйте исторические результаты с датой.

## Карта проекта

- Go 1.24; cmd/server/ — роутинг, статика, запуск и завершение сервера.
- internal/ — config, catalog, domain, handler, iiko, idempotency, middleware.
- index.html, css/style.css, js/app.js — гостевой интерфейс; demo.html — диагностика.
- data/menu_catalog.json — редактируемый локальный каталог; js/menu-data.js — витрина.
- internal/catalog/catalog.go — отдельный серверный каталог доверенных цен.
- tools/ — Python-импортёр и интеграционные утилиты; scripts/ — общие проверки.
- Тесты Go лежат рядом с кодом. Frontend не имеет npm-сборки.

## Команды

Полная локальная проверка, одинаковая на Windows, Linux и в CI:

```sh
python scripts/check.py
```

Нужны Go 1.24, Python 3.10+ и Node.js 22+. Быстрые проверки:

```sh
go test ./...
go vet ./...
node --check js/app.js
node scripts/check-menu.cjs
python -B -m unittest discover -s tools -p test_import_menu.py
python -B tools/import_menu.py --check
```

Для локального сервера настройте iiko_config.json по примеру, затем:
```sh
go run ./cmd/server
```
Для автопроверок конфигурация и ключи iiko не нужны. Go-тестам разрешите loopback:
они используют локальные httptest-серверы.

## Правила реализации

- Go форматируйте gofmt; Python — 4 пробела; HTML/JS — существующий стиль с 2 пробелами.
- Сохраняйте HTML/CSS/Vanilla JS. Не добавляйте runtime UI-библиотеки и Tailwind CDN.
- Гостевые тексты — на русском; диагностические функции — на /demo.
- Перед крупными UI-блоками согласуйте концепцию и токены, если они ещё не определены задачей.
- Сервер сам определяет цены и названия; не доверяйте значениям из браузера.
- При обновлении меню согласуйте JSON, JS и Go-каталог. Проверки должны пройти.
- Покрывайте изменённые бизнес-сценарии, ошибки iiko и повторы заказов.
- Используйте небольшие изменения и Conventional Commits; не коммитьте без поручения пользователя.
- При одновременной работе агентов используйте отдельные ветки/worktree.

## Реальные внешние действия

- Не коммитьте .env, iiko_config.json, токены и личные данные гостей.
- cmd/test-order, tools/test_order.py, /api/test-order и обычный checkout с боевой
  конфигурацией создают реальные заказы. Запускайте только по явному поручению
  на живой тест с координацией сотрудников ресторана. Это не автопроверки.
- Не выполняйте общий Python discovery по всем test_*.py: в tools/ есть боевые утилиты.
- Публикация, перезапуск боевого сервиса и миграции требуют поручения на это действие.
- Общие правила и процедуры храните в Git; секреты и машинные пути — локально.
  Правила Markdown не заменяют sandbox и настройки доступа используемого агента.
