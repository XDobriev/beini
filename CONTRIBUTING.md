# Разработка BEINI

1. Прочитайте AGENTS.md и документ по изменяемой области.
2. Проверьте Git status. Не перезаписывайте незавершённые изменения другого автора.
3. Для задачи определите наблюдаемые критерии приёмки. Для большой работы
   используйте docs/tasks/TEMPLATE.md; при параллельной работе — отдельные worktree.
4. Вносите небольшие изменения. Go форматируйте gofmt.
5. Выполните python scripts/check.py. UI дополнительно проверяйте по docs/testing.md.
6. Обновите документацию, которую затрагивает поведение или конфигурация.
7. Перед ревью проверьте diff на секреты, лишние артефакты и побочные изменения.

Коммиты — Conventional Commits: feat(api), fix(menu), docs, chore и т. п.
Описание PR: проблема, итоговое поведение, выполненные проверки и ограничения.
Для визуальных изменений приложите скриншоты мобильного и десктопного вариантов.
Не подменяйте успешными историческими результатами проверки текущего изменения.

Основные приоритеты живут в docs/roadmap.md. Подробности крупных задач — в docs/tasks/.
Не поддерживайте независимые копии одного статуса в нескольких трекерах.
После завершения задачи отметьте итог и ссылку на commit/PR, когда они появятся.

Общие правила меняются в AGENTS.md, инструкции дизайна — в docs/design-system.md.
GEMINI.md и CLAUDE.md остаются короткими входными файлами.
Проектные skills при необходимости храните в .agents/skills/ и проверяйте,
что они попадают в Git; машинные конфигурации и секреты оставляйте локально.
